1. Resumen ejecutivo

El Banco XYZ, institución con +30 años operando sobre COBOL y Shell en mainframe, moderniza su plataforma para ganar escalabilidad, resiliencia y seguridad.

Alcance

  • Migración de 3 procesos batch a Spring Batch (copia legacy + reescritura).
  • Patrón BFF para Web, Móvil y Cajeros.
  • 3 microservicios resilientes y seguros con Spring Cloud.
  • Despliegue Docker y nube (AWS).

Características

  • OAuth 2.0 + HTTPS por canal.
  • Resilience4j (Circuit Breaker/Retry/Fallback).
  • Apache Kafka (eventos productor→consumidor).
  • Config Server + Eureka + API Gateway.

4. Migración batch (Spring Batch)

3 procesos reescritos

  • Reporte de Transacciones Diarias (+ anomalías y resumen).
  • Cálculo de Intereses (cuentas ahorro/préstamo).
  • Estados de Cuenta Anuales.
  • Copia legacy en legacy/ para comparar.

Calidad de datos

  • Parser de 4 formatos de fecha (el legacy descarta ~1600 registros).
  • Retry/Skip + deduplicación por clave única.
  • JobRepository → re-ejecución idempotente.

6. Microservicios con Spring Cloud

Servicios de dominio

  • ms-clientes — perfiles (CRUD).
  • ms-cuentas — apertura, cierre, saldo, retiros.
  • ms-pagos — pagos, transferencias, depósitos.

Spring Cloud

  • Config Server — configuración central.
  • Eureka — service discovery.
  • API Gateway — enrutamiento y balanceo.
  • OAuth 2.0 — seguridad distribuida.

7. Resiliencia, seguridad y eventos

Resilience4j

Circuit Breaker + Retry + Fallback en los BFFs: ante la caída de un microservicio, el canal responde con un fallback controlado.

OAuth 2.0

Authorization Server emite JWT por canal; resource servers validan (401/403).

Kafka

Tópicos clientes, retiros, transacciones, autenticaciones.

Consistencia

ms-pagos publica "transacciones completadas" → ms-cuentas actualiza saldo (consistencia eventual).

11. Propuestas de mejora y próximos pasos

  • Observabilidad: OpenTelemetry y trazabilidad distribuida (tracing) entre BFFs y microservicios.

  • Mensajería en nube: Kafka en EC2/MSK con los microservicios conectados al broker remoto.
  • Saga: transacciones distribuidas con compensación.
